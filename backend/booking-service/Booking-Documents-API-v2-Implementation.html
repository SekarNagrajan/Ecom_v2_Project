Booking Documents API v2

Implementation Document
Prepared for: Tailwind Shipping
Date: January 28, 2026

1. Overview

This document outlines our implementation plan for the Booking Documents API v2 as specified in the client's OpenAPI specification. We have reviewed the requirements and identified our approach for each endpoint.

2. Data Storage Architecture

Important: Document metadata is retrieved directly from the file system, not from a database table.

Documents are stored in a shared folder structure organized by booking ID:

<base_path>/Ecom/{bookingId}/
    ├── invoice.pdf
    ├── customs_manifest.pdf
    └── bill_of_lading.pdf

How metadata is retrieved:

Field Source Description
fileName File System Name of the file from file.getName()
fileSize File System File size in bytes from file.length()
lastModified File System Last modified timestamp from file.lastModified()

Benefits of this approach:

  • No database schema changes required for document metadata
  • Metadata is always in sync with actual files
  • Reduced database overhead
  • Files can be managed externally if needed

Path configuration: The base path is configured in the emssetting table with modulename='Bill of Lading' and status='A'.

4. Endpoint Details

3.1 List Booking Documents

Endpoint: GET /api/v2/bookings/{bookingId}/documents

Response Format (200 OK):

[
  {
    "fileName": "customs_manifest.pdf",
    "fileSize": 102400,
    "lastModified": "2026-01-05T09:00:00Z"
  },
  {
    "fileName": "invoice.pdf",
    "fileSize": 51200,
    "lastModified": "2026-01-04T17:00:00Z"
  }
]

Implementation Notes:

  • Returns metadata for all documents attached to the specified booking
  • lastModified will be in ISO 8601 format (UTC timezone)
  • Returns empty array [] if no documents exist
  • bookingId can be booking request ID (e.g., BKON123) or confirmed booking ID (e.g., TSHG1234)

3.2 Upload Booking Documents

Endpoint: POST /api/v2/bookings/{bookingId}/documents

Request:

  • Content-Type: multipart/form-data
  • Field: files (array of binary files)

Response:

  • 201 Created - Successfully uploaded
  • 409 Conflict - File with identical name already exists

Validation Rules:

Rule Description
File Count 1-5 files per request
File Size Max 10 MB per file
Total Size Max 50 MB per request
File Types No executables (.exe, .jar, .bat, .sh, .cmd, .msi), audio, or video files
Duplicate Names Not allowed in same request

3.3 Download Document

Endpoint: GET /api/v2/bookings/{bookingId}/documents/{fileName}

Response:

  • 200 OK - Returns binary file content
  • Content-Type: application/octet-stream

Implementation Notes:

  • Returns the raw file content for download
  • fileName must be URL-encoded if it contains special characters
  • File is streamed directly without loading entire content into memory

3.4 Delete Document

Endpoint: DELETE /api/v2/bookings/{bookingId}/documents/{fileName}

Response:

  • 204 No Content - Successfully deleted
  • 404 Not Found - Document does not exist
  • 409 Conflict - Document cannot be deleted (e.g., in use by another process)
Note: This action permanently removes the document and cannot be undone.

5. Error Response Format

All error responses follow RFC 7807 Problem Details format:

{
  "detail": "The requested document was not found.",
  "title": "Not Found",
  "status": 404,
  "type": "https://api.tailwind-shipping.com/problems/not-found",
  "instance": "/api/v2/bookings/BKON123/documents/missing.pdf",
  "code": "DOCUMENT_NOT_FOUND"
}

Standard Error Responses

HTTP Status Description When Returned
400 Bad Request Invalid syntax or parameters
401 Unauthorized Missing or invalid Bearer token
403 Forbidden User doesn't have access
404 Not Found Booking or document not found
409 Conflict File already exists (upload) or cannot be deleted
500 Internal Server Error Unexpected server error
503 Service Unavailable Service temporarily unavailable

6. Authentication

All endpoints require JWT Bearer token authentication:

Authorization: Bearer <JWT_TOKEN>

The token must be obtained through the authentication endpoint and included in all requests.
